2. 核心技术主张

推理链拆成六环，逐环机械核对 已进分

「可信」不是形容词：引文逐字命中 / 理由支撑主张 / 数字可溯源可复算 / 声称范围有声明 / 涉时点有锚定 / 标注因果有机制词。
机械保证：判定口径直接复用各道零 LLM 闸的输出，不会出现「分数说链完整、警示说脱节」。分母只计本题实际触发的环，未触发记「无从判定」而非满分。
对着甲方划的核心难点（40:37）：结论并非直接推出，难点在证据与结论之间的推理链。

分量相乘不相加，一票否决留得住 已落地

四分量乘法天生不互补：引文不命中、数字无出处、答非所问，不能被其他维度救回来。
机械保证：10 维里可机械判定的部分绝交给模型自评（不让被告量刑）。置信度定位为可解释、可对比、可重算的规则融合评分，不表述为概率——0.17 ≠ 命中率，刻意不做校准表。
评分口径：置信度与冲突消解都是人工给分，解释性就是分。

改一条分析，结论跟着动 已落地

删证据、改权重、调信源可信度之后，受影响结论经同一重算入口增量回填；界面与报告出自同一套评分规则。
机械保证：全部闸为派生视图即时重算——人工修改引入无溯源数字、文件被篡改，下一次读取就现形。断链环节同步变化，工作台同屏可读。
甲方原话（41:12）：「我修改一条分析之后，你的结论可能会受到影响」。

分歧是资产，不是噪声 机制在，质量未验

多智能体常见做法是投票或平均，对立判断互相抵消、风险信号随之丢失。我们：落败结论不删除，转「少数意见」留档并挂裁决理由；未决冲突不得被抹平。
机械保证：冲突配对由程序按主体×议题维生成候选，跨主体永不进场；丢弃写入 conflict_drops 并报告披露；同主体极性对立强制补召。评价型问题不硬套收敛性——事实型看收敛，评价型看分歧是否被解释清楚。
甲方（41:23）：「消解类型是我们自己定义的类型……需要大家发散思维」。

证据必须在原文定位 最硬的一块

每条证据必须是对来源段落的逐字引文，固定三级链路：结论 → 证据（引文）→ 原文段落，逐级可下钻。
机械保证：核对是纯字符串运算，零模型调用、毫秒级、可复现：排版差异宽容，内容一致性严格。未通过核对的证据从案卷移除并进打回清单；结论失去全部证据时一并移出主报告。
甲方要求（40:12）：「我的证据必须在原文中进行定位」。

可审计的审校 ≠ 人工修正答案 已落地

五类人工动作（改写文案 / 改判冲突胜负 / 删证据 / 调权重 / 调信源可信度）全部以 human 事件写入哈希链。
机械保证：修改可审计、可还原，且还原本身也留痕（一键重置同样入链）。演示话术必须框定为审校，讲成「改答案」是自爆。
甲方红线（56:32）：「我需要看到您提交结果的整个过程，不能人工对答案进行修正」。

独立信源簇：知道哪些是抄的 主张已立，结构未做；优先级已下调

一条真信源被 90 家转载，现行覆盖分量会把 coverage 0.500 → 1.000，即置信度整体虚高 100%。多源一致在舆情场景里很可能就是转载堆量——而 EvidenceLevel.A 的定义把「多源一致」写成了加分条件。 但「很可能」这三个字已被官方样例集压低（2026-10-16 实测）：六案 486 篇里近重复只有 22 对＝4.5%， 最大的一案（吉隆 137 篇）也只有 5 对——机制真实，发生率不是常态而是少数。复放 scripts/probe_source_dedup.py。
要做的：簇成为数据结构（所属簇 / 第几代 / 事件时点），四个出口同时成立——按独立簇数计条数、跨簇进冲突队列、簇内改数即篡改检测、孤证显影「12 条证据 · 来自 1 个独立信源」。约 1 天、零 token。
答辩最能打的画面：「来自 3 个独立信源 · 含 2 代更新 · 最早出处：新华社 09-25 14:02」。
