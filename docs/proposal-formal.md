## 1. 项目概述

veritas 是面向开源情报、科研情报与企业尽调场景的**多智能体可信研判系统**。系统输入多源异构资料（文献、报告、新闻、笔记、网页、企业文档），输出带完整证据链、可解释置信度与防篡改日志的结构化研判报告，并配套可视化工作台与标准化智能体接口。

系统的核心主张可以概括为三个落点：**依据可溯源、分歧可裁决、过程可审计**。大模型研判的结论不再是一段无法追问的文字，而是一条可以逐级下钻到原文段落、可复核、可修改且修改留痕的可信链条。

| 榜单要求 | 本系统实现 | 验证方式 |
|---|---|---|
| 多智能体协同研判 | 多视角分析师独立研判（互不可见）→ 归并 → 质证 → 仲裁 | 工作台编队与冲突消解视图 |
| 证据链自动构建 | 结论 → 逐字引文 → 原文段落三级溯源，引文零大模型机械核对 | 逐条下钻演示；打回记录 |
| 结论置信度量化 | 三分量可解释评分，支持人工修改后增量重算 | 置信度分量面板；现场改权重即重算 |
| 冲突识别与消解 | 冲突清单 + 质证辩论 + 证据加权仲裁，少数意见依规保留 | 冲突与少数意见视图 |
| 推理轨迹可视化 | 证据链三级下钻 + 推理轨迹图（节点/边模型）+ 人机闭环 | 工作台全流程操作 |
| 加分项：相关/因果区分与证据等级 | 证据级关系标注，参与置信度加权 | 证据卡标注与分量说明 |
| 加分项：防篡改 | 全程哈希链研判日志，「改一字即红」 | 链校验与篡改演示 |
| 加分项：标准接口接入 | MCP 六工具，第三方结论按契约入卷 | MCP 客户端直连演示 |

## 2. 需求分析与问题定位

对榜单场景的调研显示，当前大模型辅助研判存在三类系统性缺陷：

1. **依据不可溯**。模型生成的结论缺乏可核查的原文锚点，同一问题多次询问可能得到不同答案，使用者无法区分「有据可依」与「流畅虚构」。
2. **分歧被抹平**。多智能体系统的常见做法是投票或平均，对立判断在合并时互相抵消，冲突所携带的关键风险信号随之丢失；被否定的意见没有留档，事后无法复查。
3. **过程不可审**。报告一经生成即成为静态文本，人工修改无记录、不可追溯，研判过程缺少防篡改手段，难以满足情报与尽调场景的审计要求。

针对上述问题，veritas 将「可信」从主观感受转化为三条可检查的工程约束：每条结论必须锚定经机械核对的原文依据（未通过核对的证据一律打回）、每场分歧必须给出裁决过程与理由（且败方意见保留）、每次修改必须写入可校验的账本。

## 3. 系统总体设计

### 3.1 研判流水线

系统按七步固定流水线编排，全部关键步骤留痕入链：

**信源摄取切段 → 多视角独立研判 → 引文机械核对 → 同义结论归并 → 冲突检测与质证仲裁 → 置信度融合 → 报告与日志落盘**

各步均设有降级路径：单个分析师失败只降级不中断，协同段任一步失败退化为「多结论并列、无消解记录」，最坏情况下主报告仍然产出。

### 3.2 分层架构

| 层次 | 职责 | 主要模块 |
|---|---|---|
| 证据语义层 | 信源/段落/证据/结论四级数据模型，相关-因果与证据等级入 schema | `core/evidence` |
| 摄取层 | PDF / HTML / Markdown / TXT 切段入库，信源类型与可信度声明 | `ingest/` |
| 智能体层 | 多视角编队、硬隔离独立研判、结构化输出契约 | `agents/panel`、`agents/base` |
| 协同裁决层 | 归并、冲突检测、质证辩论、仲裁；外部智能体结论入卷 | `agents/arbiter`、`agents/ingress` |
| 可信保障层 | 引文机械核对、三分量置信度、冲突簿记、哈希链、推理图、人机操作 | `core/*` |
| 交互与接口层 | 可视化工作台、MCP 标准接口、命令行管线 | `server`、`mcp_server`、`pipeline` |

## 4. 关键技术与创新点

### 4.1 硬隔离独立研判与冲突消解

研判编队由三个不同视角的分析师构成（主流评估、红队怀疑、技术推进），角色与人设支持通过配置文件替换以适配不同领域。独立研判阶段的隔离不依赖模型自觉，而是由**提示词构造保证**：每位分析师仅获得议题、资料清单与自身角色，无法接触其他分析师的任何输出，从机制上消除立场趋同与附和。

协同阶段依次执行：语义相近结论归并（证据转挂、同引文去重、全体署名继承）→ 真实对立冲突检测 → 双方各一轮书面质证（轮数护栏固定为一轮）→ 仲裁。仲裁综合**程序计算的证据强度对比**与质证质量给出裁决；**落败结论不删除**，转为「少数意见」状态保留并挂载裁决理由，供人工复查。

### 4.2 三级证据链与零大模型引文核对

每条证据必须是对所指来源段落的**逐字引文**，形成「结论 → 证据（引文）→ 来源原文段落」的固定三级链路，工作台逐级可下钻。

引文核对不依赖模型判断，而由纯字符串运算完成：引文与段落经 NFC 归一化、空白剔除、Markdown 记号剔除、全半角标点统一后做子串匹配——**排版差异予以宽容，内容一致性严格校验**；含省略号的跨段引文按省略段切分后依序命中。核对全程零模型调用、毫秒级完成、结果可复现。未通过核对的证据从案卷移除并进入打回清单，结论因此失去全部证据时一并移出主报告。该机制确保任何编造或拼接的引文都无法进入正式证据池。

### 4.3 三分量可解释置信度

每条结论的置信度由三个可解释分量乘法融合：

- **强度**：证据等级 × 信源可信度 × 因果关系加成 × 人工权重，取证据均值；
- **覆盖**：证据条数边际递增，四条饱和，单条设有覆盖下限；
- **一致性**：独立得出相近结论的分析师数占编队比例，单人结论设有下限。

分量明细（强度/覆盖/一致性/证据数/署名数/等级集合）随结论一并展示。人工在工作台删除证据、调整权重或信源可信度后，系统经同一重算入口增量回填受影响结论——界面呈现与报告输出始终出自同一套评分规则。

### 4.4 推理轨迹图与人机闭环

研判案卷可物化为节点-边模型（结论、证据、段落、信源、分析师、冲突、质证、裁决八类节点；支撑、引用、署名、对立、质证、裁定等七类关系边），供工作台与外部系统消费。

工作台支持五类人工操作：**改写结论文案、人工改判冲突胜负（含未决）、删除证据、调整证据权重、调整信源可信度**，并配备一键重置。全部人工动作以 `human` 事件写入哈希链：修改可审计，且可还原并不等于无痕——重置动作本身同样写入日志。

### 4.5 哈希链防篡改研判日志

研判全程关键事件（案例装载、各分析师完成、引文审计、归并、冲突检出与裁决、置信度计算、报告定稿、人工修改）以只追加方式写入链式日志：每条记录含负载哈希、前向哈希与记录哈希，SHA-256 串联。校验时逐条重算，可精确定位首个被篡改的记录。工作台提供篡改演示：仅在内存副本中修改一个字段，校验立即失败，磁盘文件不受影响——直观呈现「改一字即红」。

### 4.6 标准接口与可复用编排

系统经 MCP（Model Context Protocol）以 stdio 服务对外提供六个标准工具：案例列举、报告读取、链校验（三者零大模型、离线可用）、外部结论入卷（第三方智能体结论按统一证据契约入卷并过同一引文闸）、单视角研判与多智能体全流程研判（与命令行管线同一条代码路径）。任何 MCP 客户端可直接接入。

编排的可复用性体现在三个层面：编队角色配置化（`--roster` 加载自定义角色名单）、协调流水线与具体模型解耦（更换模型或网关不改变产品骨架）、语义判定与机械簿记分离（可审计部分全部为程序化实现）。

## 5. 系统实现

- **技术栈**：Python 3.10+，约 4,000 行应用代码、300 行零第三方依赖前端
- **服务与网关**：FastAPI 工作台服务、litellm 多供应商模型网关（懒加载）、MCP 官方 SDK（1.x 与 2.x 双兼容）
- **模型调用护栏**：任务级 token 总预算闸门、瞬态错误指数退避重试、响应截断续写、空内容扩容阶梯、密钥缺失调用前快速失败
- **跨平台部署**：Windows 与 macOS 一键部署脚本、自包含携带包（排除虚拟环境与本地产物，密钥不落盘）、无网络无密钥环境下的离线演示兜底
- **测试**：88 项自动化测试全部桩化、零密钥全绿，覆盖数据模型、引文核对、置信度、冲突簿记、哈希链、多智能体协同、工作台端到端（真实 HTTP 服务）、MCP 协议级握手与人机闭环契约

## 7. 当前边界与演进计划

系统对以下边界持明确说明：

- 相关与因果的区分目前由研判智能体按证据内容标注、由规则加权参与评分，尚非完整的因果推断引擎；后续计划引入对照与机制证据的结构化建模，提升因果判定的可核查性。
- 置信度定位为**可解释、可对比、可重算的规则融合评分**，服务于决策辅助与透明度，不表述为概率意义下的预测。
- 当前案例规模为六至十份信源量级；更大规模语料将演进为分批研判与检索增强的二级架构。
- 多人协同评审在数据模型层已预留（人工事件含操作者字段）。完整的多人并行修改与质证流程列入后续计划。

## 8. 结语

veritas 将「可信研判」落实为三条可检查、可实测的产品能力：**结论可溯源至原文段落，分歧经质证与仲裁后裁决留档、少数意见依规保留，人工修改与研判全程写入防篡改日志**。系统全部核心机制均为确定性程序实现并配有自动化测试，支持离线复现，欢迎实测验证。
