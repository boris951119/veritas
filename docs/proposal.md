# veritas 方案说明（答辩可读版）

> AI for Science · OPC 2026 杂交学科创新挑战赛 · 榜单《多智能体可信研判与证据链溯源》参赛方案
> 给评委看的书面材料；语言尽量白话。答辩时不必照念，抓住文中加粗的「主线句」即可。

## 1. 我们解决什么问题

开源情报、科研情报、企业尽调，越来越多人让大模型「给个判断」。  
常见糟糕体验是：

- 结论很自信，但**说不清依据从哪段原文来**；  
- 多个智能体只是简单投票，**冲突糊成平均数**；  
- 报告一旦生成，**改了也不留痕**，事后无法审计。

一句话痛点：**AI 能写结论，却很难让人信结论。**

veritas 要做的，是把「多智能体研判」变成一条可检查的流水线：

**多视角独立判断 → 形成结论 → 每条结论挂证据 → 证据接到原文 → 冲突能处理 → 人能改、改能查。**

## 2. 产品长什么样（用户视角）

输入：多份异构资料（文献、报告、新闻、笔记、网页等）。  
输出：一份结构化研判报告 + 可视化工作台 + 一份防篡改研判日志。

用户在工作台里能做的事：

| 想搞清楚的事 | 在产品里怎么看 |
|---|---|
| 这话凭什么？ | 结论 → 引文 → 原文段落，三级点开 |
| 几个 AI 吵起来了？ | 冲突清单 + 质证 + 裁决理由；少数意见单独保留 |
| 这个分数靠谱吗？ | 置信度拆成「强度 / 覆盖 / 一致性 / 链完整性」四分量，断在哪一环直接写出来 |
| 我想改一下？ | 改结论、调权重、删证据、人工改判；改完重算并入账本，也可一键重置 |
| 有没有人偷偷动过？ | 哈希链校验；演示「改一字即红」 |

演示案例三个（同一套引擎）：

1. **固态电池科研情报**——技术成熟度 / 量产前景类问题；  
2. **数据中台交付风险**——企业情报、脱敏材料，证明不只会跑科研题目；  
3. **谣言 vs 官方通报**——自媒体多数转述对上监管核查：票数不能压过证据强度，落败意见进少数意见而不是删掉。

## 3. 核心机制（讲清楚「为什么可信」）

### 3.1 多智能体：先分开写，再坐下来吵

我们至少用两类以上**不同角色**的分析师（默认三个视角，也可配置成你业务里的两派、三派）。

重要设计：**独立研判时互不可见。**  
避免「第一个说什么，后面就跟着附和」。

之后进入协调：

1. 意思接近的结论先归并；  
2. 真正对立的检出冲突；  
3. 双方各做一轮质证；  
4. 仲裁结合「程序算的证据强度」和「说理」给出胜负或未决；  
5. **败方不删除，标成少数意见保留。**

这比「简单投票」多了两样东西：**说理过程**，以及**不同意的声音还在**。

### 3.2 证据链：挂不住原文，就不配进报告

每条证据必须是**对着来源段落的逐字引文**。  
核对不用大模型「感觉像不像」，而是程序做字符串级比对——排版差异可以宽容，**内容对不上就打回**。

这是我们理解的「可信」里最硬的一刀：  
**模型可以胡说，但胡说进不了正式证据池。**

### 3.3 置信度：一个总分，四分量说人话

综合分由四部分加权和＋硬门融合（均可解释、可重算；v2 起不再连乘），逐条对应榜单硬需求 3 的
「信源可信度、数据数量与一致性、推理链完整性」：

- **强度**（信源可信度）：证据等级、信源可信度、相关/因果标注、人工权重；  
- **覆盖**（数据数量）：有几条证据撑着（不是堆越多越好到离谱，有饱和）；  
- **一致性**：有几个分析师独立走到相近结论；
- **链完整性**（推理链完整性）：把这条结论的推理链拆成六环逐环核——
  引文是否逐字命中、理由是否支撑主张、数字是否可溯源可复算、
  声称范围有无覆盖声明、涉及时点有无锚定、标因果有无机制词；
  **分母只算本题触发的环**（没写数字不因「没写数字」白捡满分），
  一环都没触发时记「无从判定」而不是满分。

第四分量与此前唯一的区别：这六件事原来只亮黄牌、不进分数，现在
「链断在哪一环」直接写进报告与工作台的分量面板，评委照榜单原文能勾到分。
判分口径与各道机械闸**同一来源**——不会出现「分数说链完整、警示说脱节」。

人工改完证据或信源后，走同一套重算入口——保证「界面上改的」和「报告里写的」是同一规则。

**高置信口径（C-24，两套数字分列、禁止平均成一个数）**：

- **自标定（真数已出，task #38 已入账）**：标定集＝自家案例 `cases/` 里 **226 条** label（`calibration/labels_self.jsonl`；口径＝模型辅助标注＋人工签字，其中 180 行逐行签、43 行走「『对』档改标率 ≤10% ⇒ 整批按草稿入账」的规则、3 行为误降复原；标签分布 **对 81／部分 126／错 19**）⇒ **ECE＝0.4067**、**高档覆盖率＝0.0（0/226）**。⚠ **一处选择效应必须同句披露**：候选池 256 行里有 **30 行未入账**（＝模型给不出可逐字定位引文的那批，大概率是更差的结论），所以下表各箱准确率是**偏乐观的上界**。可靠性曲线按 0.2 端点分**五箱**（工单原文写"六箱"与 0.2 步长自相矛盾，已按端点落地）：`0.0–0.2` n=94 准确率 **69.7%**（均值置信 0.144）／`0.2–0.4` n=109 **59.2%**（0.272）／`0.4–0.6` n=21 **66.7%**（0.483）／`0.6–0.8` n=2 **样本不足**（不印百分比，只按占比计入 ECE）／`0.8–1.0` n=0 **空**。**三条读法如实写、不粉饰**：① 我们**系统性低置信**——分数集中在 0.1～0.3 而实际准确率 60%～70%，0.41 的 ECE 几乎全部来自这个方向；② 各箱准确率**非单调**（69.7→59.2→66.7），因此不宣称"分数越高越准"，只说"排序方向大致可用、绝对值偏保守"；③ 达标行在 **labels_self 存分（v1 产物分）** 上没有高档样本可回答；v2 回灌见下条与 `scripts/score_face_v2_report.py`。复放（存分曲线）＝`python scripts/calibrate_confidence.py --labels calibration/labels_self.jsonl`（零 LLM、离线、无密钥），曲线落 `/tmp/s4runs/calib-curve-<ts>/curve.json`。
- **合式已改（C-36，2026-10-22）**：人定权重加权和＋硬门＋单参数温度已落地；标定集本身仍只有自家案例，官方 18 题不进标定集。达标线仍挂着等官方第 4 问。
- **官方 18 题验收**（提交物语义对账）：严／宽一致率等读数只在验收轨披露，**与自标定分列两处，禁止合并或平均成一个数**。
- **合式改造后的口径（C-36，v2）**：合式改造解决的是分数量纲与乘性天花板、**不解决排序能力**；改后高档非空（回灌重算 n=29）但实测准确率 **0.517＜基准 0.637**，达标线「高置信（≥0.8）正确率 ≥85%」**仍未回答**（等官方第 4 问）。复放＝`.venv/bin/python scripts/score_face_v2_report.py --labels calibration/labels_self.jsonl`。

### 3.4 推理轨迹：看得见整场是怎么走过来的

系统把研判过程物化成图：结论、证据、段落、信源、冲突、质证、裁决等节点，以及它们之间的关系边。  
工作台既能三级下钻读细节，也能从过程图看全局——方便答辩时指着屏幕讲「流程」，而不是只展示最终一段话。

### 3.5 人机闭环：人说了算的部分，也进账本

允许人工：

- 改结论文案；
- 推翻或改判冲突胜负（含未决）；
- 删证据、调权重、调信源可信度；
- 需要时重开冲突检测与仲裁；
- 改乱了？**一键重置**到管线原始产物。

所有关键人工动作以 **human 事件**写入哈希链。
**可改，不等于可偷偷改。**

### 3.6 防篡改：研判日志像账本

全程关键步骤追加进链式日志（哈希相连）。  
校验失败会明确指出坏在第几条。  
演示上可以做到：诚实副本绿灯，内存里改一个字段立刻红灯——**改一字即红**。

## 4. 评测数字（主张要有实测背书）

三案例标注集 `eval/benchmark.jsonl`（≥30 条：问题→应命中段落 / 应检出冲突 / 编造引文），零 LLM 出数：

```bash
.venv/bin/python scripts/run_eval.py
```

| 指标 | 口径 | 近期跑分 |
|---|---|---|
| BM25 Recall@K | 金标段落是否进入 Top-K | 见 `dist/eval-report.json`（含同义盲区探针） |
| 冲突召回率 | 标注对立对的机械对立词典召回（开放域冲突仍由 LLM；本数可复现） | 同上 |
| 编造检出率 | `check_quote`：假引文应拒、真引文应过 | 同上（主轴可信抓手） |

同义盲区（「应收账款」↔「回款」）在探针条上可复现为未命中——这是已知边界，不是藏着的 bug。语义 rerank / agentic 取段是演进路径，赛内以文档说明。

**真公告实测（恒兴新材）**：工作台真模型，8 份巨潮公告 / 10 问（产销、分红、异动、年报/中报、回购对撞、工商、股权、负向资料不足），约 **9.5/10**。成绩单 `eval/hengxing-10q-scorecard.md`；现场样例卡 `eval/hengxing-defense.md`（Q8 中报三数齐）。

**版式与难 PDF（答辩三句）**：① 默认文字层 PDF 走轻量抽取（`pypdf`）；② 扫描件/抽不出字 → 分诊披露，不装懂；③ 开源版式引擎（Docling）为**可插拔摄取后端**（`VERITAS_PDF_BACKEND=docling`），不进默认 U 盘依赖；解析产物按派生低可信入卷，仍过引文/数字闸。跨页无表头、横版合并格是已知边界，不是分析师「再看一眼」能补上的。

安全硬化（本机认证、哈希链签名密钥、注入变体评测集）属产品化项：演示默认本机可信边界；完整防「换 URL 张冠李戴」需签名密钥——见 `docs/dev-journal.md` 开放问题。

## 5. 加分项怎么落地（诚实讲边界）

| 榜单加分方向 | 我们怎么做 | 边界（答辩被问别慌） |
|---|---|---|
| 相关 vs 因果 | 证据上可改标注；无机制词标因果 → 黄牌 + 取消加成 | 校验因果声称，不是完整因果推断引擎 |
| 防篡改 | 哈希链 + 可选 HMAC（`VERITAS_CHAIN_KEY`）+ 工作台校验/篡改演示 + 审计包导出 | 信任可移交；不是数字证书 PKI |
| 标准接口接入 | MCP：读报告、验链、跑研判、外部结论入卷（带提交方署名） | 第三方按契约提交；假引文打回并写明是谁被拒 |

`warrant_theme` 有两条规则取并集：① 主张与所引段落的**议题主题词脱节**（词表＝延期／回款／坏账／人员流失／停工／资金链，**只在企业／谣言演示案上会命中**），② 主张与所引段落**措辞零交集**（场景无关，无阈值）。它只查**措辞**层面：措辞一致、语义不构成支撑的假支撑（官方 2.4.2 举例的「结论讲伤亡、证据讲救援部署」）**两条都查不出**，目前无任何机械防法；且主张写成「结论＋因为＋复述证据的理由」时②必然被理由半句放行，只有①有机会亮。实测（复放：`.venv/bin/python scripts/probe_warrant_gate.py`）：官方 196 条金标支撑对误伤 **3.1%**、500 对跨案乱配捕获 **44.2%**、我方六案真产物 102 条活结论亮灯 **0**、bi 演示案亮灯 **14**。

## 6. 为什么说协调机制「可复用」（答辩重点）

评委常问：是不是只能演示这一个题？

我们的回答分三层：

1. **编队可配置**  
   角色名和人设从配置加载（`--roster` 一个 YAML 文件即可），不写死业务。换领域就换 roster，协调流程不变。

2. **协调是固定流水线，语义交给可替换的模型**  
   归并 / 冲突检测 / 质证 / 仲裁是稳定步骤；换模型、换网关，不换产品骨架。单步失败会降级，最坏也能出报告。

3. **标准接口进得来、出得去**  
   外部 Agent 可通过 MCP 读产物、验链、发起研判，也可把自家结论按同一证据契约入卷。  
   我们卖的是**可信研判中枢**，不是又一个封闭聊天机器人。

三个案例（科研 + 企业交付风险 + 多数派错）用来证明：**同一引擎，换问题域、换对立结构，仍可跑。**

## 8. 答辩口述提纲（3 分钟版）

若老师说「先用三分钟讲清楚」：

1. **问题**：AI 结论难追问、冲突处理粗、改动不可审计。  
2. **做法**：多视角独立研判 → 证据必须挂原文 → 冲突可裁决且保留少数意见 → 人可改且入链 → 哈希防篡改。  
3. **证明**（只做三下）：下钻到原文；改一个资料里没有的数字，黄灯亮且综合意见跟着变；篡改演示变红。编队可配、MCP 可接入，等被问再讲。  
4. **被问「测过真公告吗」**：切「恒兴新材-评测」→ Q8 中报三数齐（见 `eval/hengxing-defense.md`），一句带过约 9.5/10。  
5. **收束**：我们把「可信」从口号落成三条可检查的产品能力——**挂得住、吵得清、改得明。**

## 9. 可能被问到的题（白话答法）

**Q：和「多 Agent 聊天」有什么不一样？**  
A：独立隔离写结论；冲突有质证和裁决；少数意见保留；证据过机械核对；全过程可审计。不是群聊纪要。

**Q：引文核对会不会太死板？**  
A：刻意偏严。情报场景宁可少一条证据，也不让编造引文混进正式报告。排版差异已做宽容，内容造假过不了。

**Q：置信度 0.73 是什么科学含义？**  
A：它是规则融合分，不是概率预测。价值在于**可解释、可对比、改完可重算**。我们不把它包装成绝对真理，而是决策辅助的透明度工具。自标定轨已经量到真数并如实放在这里：**226 条自家案例人签 label ⇒ ECE＝0.4067、高档覆盖率＝0.0**，方向是**我们系统性低置信**（分数 0.1～0.3 那堆实际准确率 60%～70%），且各箱准确率**非单调**——所以我们说"排序方向大致可用"，不说"分数越高越准"；另外候选池 256 行里有 **30 行未入账**（模型给不出可逐字定位引文的那批、大概率更差），所以这些准确率是**偏乐观的上界**。该轨与官方 18 题验收轨分列两处，不平均成一个「正确率」；复放命令＝`python scripts/calibrate_confidence.py --labels calibration/labels_self.jsonl`（零 LLM、离线）。

**Q：人改了会不会破坏可信？**  
A：人本来就该参与。关键是改动进哈希链，事后可追问。可信 ≠ 无人；可信 = 可检查。

**Q：怎么接到我们已有的智能体？**  
A：走 MCP。可读报告、验链；也可把外部结论按契约入卷，统一过引文闸和后续协同。

**Q：三周冲刺的完成度如何？靠什么保证质量？**  
A：榜单硬需求与加分项已全部落地（工作台可现场实测）；机械闸与簿记全程程序化、可复现；自动化测试 + 标注集三指标防「口号可信」；离线兜底保证断网也能完整演示。

## 10. 一句话定位（可印在封面）

**veritas：让多智能体研判「说得出依据、吵得清分歧、改得留痕迹」。**
