# veritas 方案说明（答辩可读版）

> 给评委看的书面材料；语言尽量白话。你答辩时不必照念，抓住文中加粗的「主线句」即可。

---

## 1. 我们解决什么问题

开源情报、科研情报、企业尽调，越来越多人让大模型「给个判断」。  
常见糟糕体验是：

- 结论很自信，但**说不清依据从哪段原文来**；  
- 多个智能体只是简单投票，**冲突糊成平均数**；  
- 报告一旦生成，**改了也不留痕**，事后无法审计。

一句话痛点：**AI 能写结论，却很难让人信结论。**

veritas 要做的，是把「多智能体研判」变成一条可检查的流水线：

**多视角独立判断 → 形成结论 → 每条结论挂证据 → 证据接到原文 → 冲突能处理 → 人能改、改能查。**

## 2. 产品长什么样（用户视角）

输入：多份异构资料（文献、报告、新闻、笔记、网页等）。  
输出：一份结构化研判报告 + 可视化工作台 + 一份防篡改研判日志。

用户在工作台里能做的事：

| 想搞清楚的事 | 在产品里怎么看 |
|---|---|
| 这话凭什么？ | 结论 → 引文 → 原文段落，三级点开 |
| 几个 AI 吵起来了？ | 冲突清单 + 质证 + 裁决理由；少数意见单独保留 |
| 这个分数靠谱吗？ | 置信度拆成「强度 / 覆盖 / 一致性」三分量 |
| 我想改一下？ | 改结论、调权重、删证据、人工改判；改完重算并入账本 |
| 有没有人偷偷动过？ | 哈希链校验；演示「改一字即红」 |

演示案例两个（同一套引擎）：

1. **固态电池科研情报**——技术成熟度 / 量产前景类问题；  
2. **数据中台交付风险**——企业情报、脱敏材料，证明不只会跑科研题目。

## 3. 核心机制（讲清楚「为什么可信」）

### 3.1 多智能体：先分开写，再坐下来吵

我们至少用两类以上**不同角色**的分析师（默认三个视角，也可配置成你业务里的两派、三派）。

重要设计：**独立研判时互不可见。**  
避免「第一个说什么，后面就跟着附和」。

之后进入协调：

1. 意思接近的结论先归并；  
2. 真正对立的检出冲突；  
3. 双方各做一轮质证；  
4. 仲裁结合「程序算的证据强度」和「说理」给出胜负或未决；  
5. **败方不删除，标成少数意见保留。**

这比「简单投票」多了两样东西：**说理过程**，以及**不同意的声音还在**。

### 3.2 证据链：挂不住原文，就不配进报告

每条证据必须是**对着来源段落的逐字引文**。  
核对不用大模型「感觉像不像」，而是程序做字符串级比对——排版差异可以宽容，**内容对不上就打回**。

这是我们理解的「可信」里最硬的一刀：  
**模型可以胡说，但胡说进不了正式证据池。**

### 3.3 置信度：一个总分，三分量说人话

综合分由三部分相乘融合（均可解释、可重算）：

- **强度**：证据等级、信源可信度、相关/因果标注、人工权重；  
- **覆盖**：有几条证据撑着（不是堆越多越好到离谱，有饱和）；  
- **一致性**：有几个分析师独立走到相近结论。

人工改完证据或信源后，走同一套重算入口——保证「界面上改的」和「报告里写的」是同一规则。

### 3.4 推理轨迹：看得见整场是怎么走过来的

系统把研判过程物化成图：结论、证据、段落、信源、冲突、质证、裁决等节点，以及它们之间的关系边。  
工作台既能三级下钻读细节，也能从过程图看全局——方便答辩时指着屏幕讲「流程」，而不是只展示最终一段话。

### 3.5 人机闭环：人说了算的部分，也进账本

允许人工：

- 改结论文案；  
- 推翻或改判冲突胜负（含未决）；  
- 删证据、调权重、调信源可信度；  
- 需要时重开冲突检测与仲裁。

所有关键人工动作以 **human 事件**写入哈希链。  
**可改，不等于可偷偷改。**

### 3.6 防篡改：研判日志像账本

全程关键步骤追加进链式日志（哈希相连）。  
校验失败会明确指出坏在第几条。  
演示上可以做到：诚实副本绿灯，内存里改一个字段立刻红灯——**改一字即红**。

## 4. 加分项怎么落地（诚实讲边界）

| 榜单加分方向 | 我们怎么做 | 边界（答辩被问别慌） |
|---|---|---|
| 相关 vs 因果 | 证据上标注，因果在计分上有加成 | 标注由研判给出 + 规则加权；不是完整因果推断引擎 |
| 防篡改 | 哈希链 + 工作台校验/篡改演示 | 面向研判过程审计，不是数字证书 PKI |
| 标准接口接入 | MCP：读报告、验链、跑研判、外部结论入卷 | 第三方按契约提交结论；假引文仍过机械闸 |

## 5. 为什么说协调机制「可复用」（答辩重点）

评委常问：是不是只能演示这一个题？

我们的回答分三层：

1. **编队可配置**  
   角色名和人设从配置加载，不写死业务。换领域就换 roster，协调流程不变。

2. **协调是固定流水线，语义交给可替换的模型**  
   归并 / 冲突检测 / 质证 / 仲裁是稳定步骤；换模型、换网关，不换产品骨架。单步失败会降级，保证「最坏也能出报告」。

3. **标准接口进得来、出得去**  
   外部 Agent 可通过 MCP 读产物、验链、发起研判，也可把自家结论按同一证据契约入卷。  
   我们卖的是**可信研判中枢**，不是又一个封闭聊天机器人。

两个案例（科研 + 企业交付风险）用来证明：**同一引擎，换问题域仍可跑。**

## 7. 答辩口述提纲（3 分钟版）

若老师说「先用三分钟讲清楚」：

1. **问题**：AI 结论难追问、冲突处理粗、改动不可审计。  
2. **做法**：多视角独立研判 → 证据必须挂原文 → 冲突可裁决且保留少数意见 → 人可改且入链 → 哈希防篡改。  
3. **证明**：现场下钻到原文；改一处看重算；篡改演示变红；提一句编队可配 + MCP 可接入。  
4. **收束**：我们把「可信」从口号落成三条可检查的产品能力——**挂得住、吵得清、改得明。**

## 8. 可能被问到的题（白话答法）

**Q：和「多 Agent 聊天」有什么不一样？**  
A：独立隔离写结论；冲突有质证和裁决；少数意见保留；证据过机械核对；全过程可审计。不是群聊纪要。

**Q：引文核对会不会太死板？**  
A：刻意偏严。情报场景宁可少一条证据，也不让编造引文混进正式报告。排版差异已做宽容，内容造假过不了。

**Q：置信度 0.73 是什么科学含义？**  
A：它是规则融合分，不是概率预测。价值在于**可解释、可对比、改完可重算**。我们不把它包装成绝对真理，而是决策辅助的透明度工具。

**Q：人改了会不会破坏可信？**  
A：人本来就该参与。关键是改动进哈希链，事后可追问。可信 ≠ 无人；可信 = 可检查。

**Q：怎么接到我们已有的智能体？**  
A：走 MCP。可读报告、验链；也可把外部结论按契约入卷，统一过引文闸和后续协同。

**Q：21 天能做完吗？靠不靠谱？**  
A：范围盯死榜单硬需求；机械闸与簿记优先；模型调用可降级；测试先行保证回归。演示与离线兜底保证现场可讲。
