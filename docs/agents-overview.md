# veritas 智能体架构总览（答辩用）

> 回应质疑「你们是不是单智能体多模型」。一页纸答案 + 数据源
> （`app/agents/registry.py`，清单可随 roster 动态生成）。

## 一、判定：多智能体 ≠ 多模型

通行定义（多智能体辩论范式，Du et al. / AgentVerse / MetaGPT）：
**智能体 = 角色 + 独立上下文 + 输出契约**。同底座模型不同角色即标准
做法；模型异构只是多样性的一根轴。veritas 是 **10+ 个角色智能体**
的协同系统——赛题批评的「独立判断或简单投票」正是我们的反面：
独立研判之后有归并、冲突检测、质证辩论、仲裁、少数意见保留、
主席汇总。

## 二、协同协议（一句话版）

```
3 分析师（硬隔离并行研判，互不可见）
   → 归并者（同义成组） → 冲突审查员（找对立对）
   → 质证者×2（一轮书面辩论）→ 仲裁者（证据强度=程序算，新近度只做
     tie-break 提示；败方保留为少数意见）
   → 主席（输入封闭：只见已过闸结论；输出过四道闸；零 LLM 模板兜底）
全程：零 LLM 机械闸族拦截（引文逐字/计算复算/数字溯源/计数/守恒/
话语/时序/前提/注入/对撞台账），每个动作入哈希链。
```

## 四、模型异构：已落地并实测（不是路线图）

- roster 支持 per-agent `model` 字段（`build_panel` 按角色分模型）；
- **实测**（2026-10-01，bi 案例，`config/roster-hetero.yaml`）：三名
  分析师分属三个模型族——qwen3.8-max（主流）/ glm-5.3（红队）/
  deepseek-v4-pro（技术）——全部独立研判成功，`analyst_done` 链事件
  记录各自模型；百炼 token-plan 网关 10 模型全部冒烟可用；
- **模型链回退**：主模型超时/网关错误/JSON 畸形/空响应时自动换下一
  登记模型（预算尽/任务中止/密钥缺失不换腿）——单腿故障不放弃角色；
- 同模型的**错误相关性**由三层对冲：零 LLM 机械闸（编造必被抓）、
  冲突消解（解读分歧显式化）、人工复核（工作台全动作入链）。

## 五、答辩口径（问「是不是同一模型跑三次？」）

> 不是投票，是协同。我们有 10+ 个角色智能体：三个视角分析师在
> 硬隔离下独立研判（互不可见对方输出），归并者把同义结论成组，
> 冲突审查员找对立，双方一轮质证，仲裁者按**程序计算的证据强度**
> 裁决并保留少数意见，主席把已过闸结论汇总成正面回答——每个智能体
> 的输出都过对应的机械闸。模型异构是配置项（roster 的 model 字段），
> 当前网关只开放一个模型，我们用角色多样性保证视角多样性；同模型
> 的错误相关性由零 LLM 机械闸与人工复核对冲——这正是「模型负责
> 主张、程序负责复算」的架构用意。
