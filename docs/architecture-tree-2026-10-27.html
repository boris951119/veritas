veritas 流水线步骤树

从上到下：从「用户丢材料＋提问」走到「交官方 JSON」· 花盆树干版 · 2026-10-27

读法：从上往下＝流程前进（01 顶 → 27 底）；花盆＝入口在顶；彩色竖干＝同一条流水线；左右交替水平枝。橙色卡＝当前主修＝装窗／续盒看全（其中"续盒"只量过、还没进生产）。红底标签＝已知问题（仅标有 HANDOFF／量尺证据的）。每步一两句白话。点橙主修／红问题／蓝要点标签 → 弹出仍有效的关键信息（白话＋可选量尺）。

入口 · 用户丢材料＋提问 · 往下走
01丢材料

工作台上传文件夹／散文件；或 CLI 指定案例目录；官方案走 raw_documents。

02写提问／议题

同一入口带上问题文本；可写入 manifest，或官方 questions.json（question_id＋question）。

03点「开始研判」

工作台 /api/run，或命令行跑 pipeline；官方案一案多题循环。

04落盘成案卷

新建 user-* 导入案，或往已有导入案追加；示例案不许往里塞文件。

05分诊读文件 要点·7道丢料口 对比赛无影响

扫 PDF／文本／Office／HTML；压缩包先拆封；读不动、超限、跳过的都记进分诊账本。

06切片＋文本修补 要点·切段劈数

长文切成段；修断行、粘数字等抽取疤痕，方便后面检索和引文。

07大库选料（过阈值才做）

文件很多时先收窄成「本次案卷」，并披露选了谁、丢了谁；小案整卷进，不建索引。

08图片 OCR（有图才做）

扫描件／插图用视觉模型转成文字段，再并进同一案卷。

09问句同义拓展 要点·云端未验

原问＋变体给后面 BM25 用；机械闸拦住换主体、瞎编实体。

10议题预检／对撞／去重／相关性 病因5·台账双向

前提与槽位、数字事实台账对撞、近重复、注入扫描、信源高／低／零相关分层。

11槽位不齐 → 早退回读

口语议题缺关键槽时直接回读确认，不烧分析师、不装箱。

12模型纪律画像探测

先摸清模型听话档位，后面提示词与技能规则按档位收紧或放宽。

13BM25 精排 当前主修带

按拓展后的问句给段落打分排序；找得到，才谈得上往后装。

14对齐窗口缩预算 当前主修

用「和生产同形」的提示词估会不会超窗；超了就有界缩字预算，装不下要披露。

15预算装箱（单窗） 当前主修 L2装不下／窗口满箱

按分数把段装进上下文；全员同料钉死。装不下的段记排除原因。

16续盒看全（多箱） 主修·未进生产 只量过·未合入

单窗塞不下就拆成多箱续喂（有上限）；末箱归并。探窗定盒 → 窗仍不够才续盒。生产里暂时还没接，点标签看量了多少。

17三分析师并行 L3引用不足 病因1·双峰

每人只见议题＋同一盒材料＋自身角色，互看不到别人输出；有人空交付记减员。

18引文逐字核对 主张·原文定位

挂不上原文的引用直接打掉，结论不能空口。

19数字程序复算 病因2·不管推理

能算的加减乘除交给程序，不靠模型口算；出错进下一环。

20二次定向补漏 要点·刀十一半过

第一轮没引用的关键段，再定向喂一轮（主题词优先，空则 BM25×已装箱回退）。

21打回修复环（有数字问题时）

把算错的地方打回分析师改；接受率写进账本。

22归并 → 冲突 → 质证 → 仲裁 2.5冲突口径

多视角结论先合并；对撞的两边互相质证，再由仲裁定输赢。

23结论依赖边

标出谁依赖谁；前提断了后面会降级。

24置信度融合 主张·硬门＋转载

因果主张闸＋一致性等规则重算多数／异议结论的可信度。

25主席汇总 2.3部分一致

收成可读叙事；未答子问、未用关键段写进待办／缺口。

26写出报告与链

report.md 给人看，report.json 给程序，chain.jsonl 记全程事件。

27官方 JSON 打包交卷 2.2条目F1低／2.4召回弱

官方案：材料只载一次 → 每题各跑一遍 → export_official 打出赛题格式提交物。
