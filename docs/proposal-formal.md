## 1. 项目概述

veritas 是面向开源情报、科研情报与企业尽调场景的**多智能体可信研判系统**。系统输入多源异构资料（文献、报告、新闻、笔记、网页、企业文档），输出带完整证据链、可解释置信度与防篡改日志的结构化研判报告，并配套可视化工作台与标准化智能体接口。

系统的核心主张可以概括为三个落点：**依据可溯源、分歧可裁决、过程可审计**。大模型研判的结论不再是一段无法追问的文字，而是一条可以逐级下钻到原文段落、可复核、可修改且修改留痕的可信链条。

| 榜单要求 | 本系统实现 | 验证方式 |
|---|---|---|
| 多智能体协同研判 | 10+ 角色智能体（三视角分析师硬隔离 → 归并 → 质证 → 仲裁 → 主席汇总正面回答议题）,模型异构为配置项 | 智能体清单与协议图（docs/agents-overview.md）;冲突消解与综合意见视图 |
| 证据链自动构建 | 结论 → 逐字引文 → 原文段落三级溯源，引文零大模型机械核对 | 逐条下钻演示；打回记录 |
| 结论置信度量化 | 三分量可解释评分，支持人工修改后增量重算 | 置信度分量面板；现场改权重即重算 |
| 冲突识别与消解 | 冲突清单 + 质证辩论 + 证据加权仲裁，少数意见依规保留 | 冲突与少数意见视图 |
| 推理轨迹可视化 | 证据链三级下钻 + 推理轨迹图（节点/边模型）+ 人机闭环 | 工作台全流程操作 |
| 加分项：相关/因果区分与证据等级 | 证据级关系标注，参与置信度加权 | 证据卡标注与分量说明 |
| 加分项：防篡改 | 全程哈希链研判日志，「改一字即红」 | 链校验与篡改演示 |
| 加分项：标准接口接入 | MCP 六工具，第三方结论按契约入卷 | MCP 客户端直连演示 |

## 2. 需求分析与问题定位

对榜单场景的调研显示，当前大模型辅助研判存在三类系统性缺陷：

1. **依据不可溯**。模型生成的结论缺乏可核查的原文锚点，同一问题多次询问可能得到不同答案，使用者无法区分「有据可依」与「流畅虚构」。
2. **分歧被抹平**。多智能体系统的常见做法是投票或平均，对立判断在合并时互相抵消，冲突所携带的关键风险信号随之丢失；被否定的意见没有留档，事后无法复查。
3. **过程不可审**。报告一经生成即成为静态文本，人工修改无记录、不可追溯，研判过程缺少防篡改手段，难以满足情报与尽调场景的审计要求。

针对上述问题，veritas 将「可信」从主观感受转化为三条可检查的工程约束：每条结论必须锚定经机械核对的原文依据（未通过核对的证据一律打回）、每场分歧必须给出裁决过程与理由（且败方意见保留）、每次修改必须写入可校验的账本。

## 3. 系统总体设计

### 3.1 研判流水线

系统按固定流水线编排，全程穿插**零大模型机械核对闸**（模型负责主张、程序负责复算），全部关键步骤留痕入链：

**信源安全摄取（压缩包四道边界/链接清单/图片检测/输入分诊账本）→ 议题预检与前提核对 → 事实对撞台账（同实体同指标不同值机械检出）→ 注入扫描与重复排除 → 相关性分层（零相关不进提示词但披露）→ 资料预算装箱（BM25 精排）→ 模型画像探测（纪律遵从分档）→ 多视角独立研判 → 引文逐字核对（打回）→ 数字机械核对（算式复算+溯源）→ 打回修复环（变好才接受）→ 同义归并 → 冲突检测与质证仲裁 → 话语与时序核对 → 主席汇总（正面回答议题，输出过四道闸）→ 置信度融合 → 报告与日志落盘**

各步均设有降级路径：单个分析师失败只降级不中断，协同段任一步失败退化为「多结论并列、无消解记录」，图片转码/链接抓取失败回退为诚实披露——最坏情况下主报告与完整失败原因仍然产出。

### 3.2 分层架构

| 层次 | 职责 | 主要模块 |
|---|---|---|
| 证据语义层 | 信源/段落/证据/结论四级数据模型，相关-因果与证据等级入 schema | `core/evidence` |
| 摄取层 | PDF / HTML / Markdown / TXT 切段入库，信源类型与可信度声明 | `ingest/` |
| 智能体层 | 多视角编队、硬隔离独立研判、结构化输出契约 | `agents/panel`、`agents/base` |
| 协同裁决层 | 归并、冲突检测、质证辩论、仲裁；外部智能体结论入卷 | `agents/arbiter`、`agents/ingress` |
| 可信保障层 | 引文机械核对、三分量置信度、冲突簿记、哈希链、推理图、人机操作 | `core/*` |
| 交互与接口层 | 可视化工作台、MCP 标准接口、命令行管线 | `server`、`mcp_server`、`pipeline` |

## 4. 关键技术与创新点

### 4.1 硬隔离独立研判与冲突消解

研判编队由三个不同视角的分析师构成（主流评估、红队怀疑、技术推进），角色与人设支持通过配置文件替换以适配不同领域。独立研判阶段的隔离不依赖模型自觉，而是由**提示词构造保证**：每位分析师仅获得议题、资料清单与自身角色，无法接触其他分析师的任何输出，从机制上消除立场趋同与附和。

协同阶段依次执行：语义相近结论归并（证据转挂、同引文去重、全体署名继承）→ 真实对立冲突检测 → 双方各一轮书面质证（轮数护栏固定为一轮）→ 仲裁。仲裁综合**程序计算的证据强度对比**与质证质量给出裁决；**落败结论不删除**，转为「少数意见」状态保留并挂载裁决理由，供人工复查。

### 4.2 三级证据链与零大模型引文核对

每条证据必须是对所指来源段落的**逐字引文**，形成「结论 → 证据（引文）→ 来源原文段落」的固定三级链路，工作台逐级可下钻。

引文核对不依赖模型判断，而由纯字符串运算完成：引文与段落经 NFC 归一化、空白剔除、Markdown 记号剔除、全半角标点统一后做子串匹配——**排版差异予以宽容，内容一致性严格校验**；含省略号的跨段引文按省略段切分后依序命中。核对全程零模型调用、毫秒级完成、结果可复现。未通过核对的证据从案卷移除并进入打回清单，结论因此失去全部证据时一并移出主报告。该机制确保任何编造或拼接的引文都无法进入正式证据池。

### 4.3 三分量可解释置信度

每条结论的置信度由三个可解释分量乘法融合：

- **强度**：证据等级 × 信源可信度 × 因果关系加成 × 人工权重，取证据均值；
- **覆盖**：证据条数边际递增，四条饱和，单条设有覆盖下限；
- **一致性**：独立得出相近结论的分析师数占编队比例，单人结论设有下限。

分量明细（强度/覆盖/一致性/证据数/署名数/等级集合）随结论一并展示。人工在工作台删除证据、调整权重或信源可信度后，系统经同一重算入口增量回填受影响结论——界面呈现与报告输出始终出自同一套评分规则。

### 4.4 推理轨迹图与人机闭环

研判案卷可物化为节点-边模型（结论、证据、段落、信源、分析师、冲突、质证、裁决八类节点；支撑、引用、署名、对立、质证、裁定等七类关系边），供工作台与外部系统消费。

工作台支持五类人工操作：**改写结论文案、人工改判冲突胜负（含未决）、删除证据、调整证据权重、调整信源可信度**，并配备一键重置。全部人工动作以 `human` 事件写入哈希链：修改可审计，且可还原并不等于无痕——重置动作本身同样写入日志。

### 4.5 哈希链防篡改研判日志

研判全程关键事件（案例装载、各分析师完成、引文审计、归并、冲突检出与裁决、置信度计算、报告定稿、人工修改）以只追加方式写入链式日志：每条记录含负载哈希、前向哈希与记录哈希，SHA-256 串联。校验时逐条重算，可精确定位首个被篡改的记录。工作台提供篡改演示：仅在内存副本中修改一个字段，校验立即失败，磁盘文件不受影响——直观呈现「改一字即红」。

### 4.6 标准接口与可复用编排

系统经 MCP（Model Context Protocol）以 stdio 服务对外提供六个标准工具：案例列举、报告读取、链校验（三者零大模型、离线可用）、外部结论入卷（第三方智能体结论按统一证据契约入卷并过同一引文闸）、单视角研判与多智能体全流程研判（与命令行管线同一条代码路径）。任何 MCP 客户端可直接接入。

编排的可复用性体现在三个层面：编队角色配置化（`--roster` 加载自定义角色名单）、协调流水线与具体模型解耦（更换模型或网关不改变产品骨架）、语义判定与机械簿记分离（可审计部分全部为程序化实现）。

### 4.7 主席汇总层：从「结论清单」到「正面回答」

赛题要求「仲裁汇总」——系统在仲裁之外设**主席智能体**：输入封闭（仅见已过全部机械闸的结论、冲突与少数意见，无权接触原始资料），输出为结构化综合意见（一句话正面回答 + 逐要点概括 + 分歧与资料缺口明示），每要点挂结论编号。主席输出经四道机械闸：引用存在性、**完整性**（每条多数结论必须有着落，遗漏由程序自动补全并标注）、**数字溯源**（概括中的每个数字必须能在所引结论原文找到，违规点以原文顶替而非丢弃）、分歧不得抹平（未决冲突与少数意见被略过时由模板强制补回）。模型不可用或输出违规时回退为**零大模型模板汇总**——演示永不空。

### 4.8 零大模型机械闸族：模型负责主张，程序负责复算

引文核对之外的六类数字与话语风险由确定性代码拦截，全部可复算、可测试：

- **计算复算**：结论与说明中的显式算式（比率/合计/差额/乘算，含万/亿/百分号单位）由程序代入重算，不符打回；算式输入数无法在所引材料定位（编造输入）同样打回；
- **数字溯源**：结论中每个数字必须出自所引材料或已验证算式（来源外数字亮牌）；日期、年份、序数、计数量词自动豁免；
- **事实对撞台账**：跨信源抽取「实体×指标×数值」三元组，同键不同值机械检出——信源间数字矛盾不再依赖分析师恰好引到；对撞清单注入提示词要求结论正面回应，并进报告独立章节；
- **归并守恒与话语核对**：归并结论不得引入成员之外的新数字（概括漂移）；质证引文须逐字命中（防稻草人）；仲裁理由引用的编号必须存在；
- **措辞一致性**：证据等级与信源类型不符（低可信信源标 A 级）亮牌；因果标注无机制性表述则取消加成按相关计分；
- **时序核对**：信源时点入账（manifest 声明或正文抽取），结论引用旧时点资料而存在新时点数值时亮牌，结论未锚定时点亮牌；仲裁获信源时点对比作为平局考量。

全部闸为**派生视图即时重算**：人工修改引入无溯源数字、文件被篡改，都会在下一次读取时现形。

### 4.9 输入夹层：假定输入是敌意的

- **安全摄取**：压缩包魔数识别与四道边界（路径穿越逐段拒、解压炸弹声明预检+流式上限双保险、条目数封顶、嵌套深度限制），加密/损坏包降级披露不中断；子目录有界遍历；纯图片与扫描件逐份披露「未解析」；PDF 默认轻量抽取（pypdf），可选开源版式后端 Docling（`VERITAS_PDF_BACKEND=docling`，非默认依赖，失败回退；产物派生低可信入卷）；链接清单默认仅披露，显式开启后逐条抓取（超时/大小/条数上限）并落本地缓存（**内容哈希完整性校验**，防缓存投毒），成功者成为低可信派生信源；
- **注入防御**：全部进提示词的资料包「不可信数据」显式围栏；指令注入特征扫描（含对模型产出回流文本的**二阶注入**扫描）；分析智能体无工具调用能力——注入在结构上只能以「被机械闸打回」收场；
- **输入分诊账本**：每个文件（含压缩包条目）一条路由记录（入卷/抓取/转写/排除及理由），报告整章呈现——读了什么、没读什么、为什么，账面可见；
- **质量兜底**：文件级哈希去重（重复件不计票防一致性虚增）、shingle 近重复检出（同源转述警示）、相关性三档分层（零相关不进提示词但披露，同义表述经对撞主题词汇桥接兜底，人工可强制纳入/排除并入链）、BM25 段级检索与预算装箱（超大输入在预算内保留最优覆盖，未装入段落全部披露）。

### 4.10 模型自适应与循证验证纪律

- **模型画像**：接入任意网关前，先以一次微型调用探测模型的纪律遵从度（引文逐字/算式纪律/转述语气三项机械判分）；不遵从的模型自动改用强化版规则与结构化输出契约，并启用打回修复环——**用户接什么模型未知，系统自适应，而非要求用户迁就**；多模型异构经编队配置按角色声明；
- **skill 注册表**：提示词纪律按案卷特征条件触发（表格密度/数字密度/低可信占比等），每条纪律必须配对一道机械闸（「没有闸的 skill 是许愿」）；启用与否由预注册的开关对照实验（A/B）实证裁决——首轮实验在真实网关上停用了三条无可度量红绿差的纪律，实证数据与停用理由随代码入库；
- **图片转码**：网关具备视觉端点时，图片逐字转写为低可信派生信源（先验 0.3，「读不清标 [无法辨认]、禁止解读」契约），与本地文件同权过全套机械闸；无视觉端点自动降级为披露。

## 5. 系统实现

- **技术栈**：Python 3.10+，约 9,000 行应用代码、约 400 行零第三方依赖前端
- **服务与网关**：FastAPI 工作台服务、litellm 多供应商模型网关（懒加载）、MCP 官方 SDK（1.x 与 2.x 双兼容）
- **模型调用护栏**：任务级 token 总预算闸门、瞬态错误指数退避重试、响应截断续写、空内容扩容阶梯、密钥缺失调用前快速失败
- **跨平台部署**：Windows 与 macOS 一键部署脚本、自包含携带包（排除虚拟环境与本地产物，密钥不落盘）、无网络无密钥环境下的离线演示兜底
- **测试**：250 项自动化测试全部桩化、零密钥全绿，覆盖数据模型、引文核对、数字与话语机械闸、议题预检、事实对撞、时序核对、相关性分层、检索装箱、输入分诊与敌意样本（路径穿越/解压炸弹/注入/缓存投毒）、模型自适应、主席汇总、权限视图、多智能体协同、工作台端到端（真实 HTTP 服务）、MCP 协议级握手与人机闭环契约；另备产物归一化比对工具（重构「不改变行为」的验收判据）与签名审计脚本（函数参数超标清单）

| 信源 | 乐观报告、怀疑笔记、新闻汇编（三类立场冲突） | 六类脱敏企业文档：技术方案、进度汇报、来往账目×2、人员清单、管理计划 |
| 展示重点 | 三视角对立、质证与仲裁全程、少数意见保留 | 一手账目数据加权、实质冲突、拼接引文被机械闸打回、四组跨信源数字对撞、输入分诊账本 |
| 数据合规 | 公开技术情报 | 机构名、人员联系方式、分包商名称全量脱敏后构建 |

第三案例面向舆情场景（拓尔思核心业务）：**谣言 vs 官方通告**——微博爆料、转发链与官方通报三类信源对立，系统给出「多数结论为官方通报、谣言降为少数意见、程序按证据强度翻案」的完整研判，并全程留痕。

**评测双轨原则**：边界用例=合成可控，准确率评测=真实披露文件。系统对两类验证材料严格分轨——**边界与对抗用例采用合成材料**（可控地构造编造引文、错误算术、指令注入、路径穿越、解压炸弹等攻击面，56 项用例带机器可判定预期），用于验证机械闸与防御层的拦截能力；**准确率评测采用真实披露文件**（巨潮资讯公开的七家上市公司两年年报摘要、业绩预告、更正公告及 SEC EDGAR 纳斯达克 AOSL 官方文件，约 2,000 份原样保存、不做任何修改），用于度量真实场景下的检索召回、冲突检出与数字正确率。合成材料证明「想得到的攻击拦得住」，真实材料证明「真实场景下有据可查」——两者互不替代。工作台演示动线覆盖证据下钻、置信度分量、人工修改重算、人工改判、一键重置与防篡改校验。

## 7. 当前边界与演进计划

系统对以下边界持明确说明：

- 相关与因果的区分目前由研判智能体按证据内容标注、由规则加权参与评分，尚非完整的因果推断引擎；后续计划引入对照与机制证据的结构化建模，提升因果判定的可核查性。
- 置信度定位为**可解释、可对比、可重算的规则融合评分**，服务于决策辅助与透明度，不表述为概率意义下的预测。
- 当前案例规模为六至十份信源量级；系统已内置 BM25 段级检索与预算装箱（超大输入在预算内保最优覆盖并披露未读清单），更大规模语料的语义检索与按需取段的智能体式分析列入演进计划（渲染引擎、语义重排同为可插拔位）。
- 准确性的诚实边界：系统保证**不实必被检出**（编造引文、无源数字、算术错误由机械闸拦截）与**残余不确定性全部可见**（置信度分量、少数意见、资料缺口、议题表述分级披露），不承诺语义推理层面的零错误——该残余由多视角制衡与人工复核收敛。
- 评测材料双轨：**边界用例=合成可控，准确率评测=真实披露文件**——合成材料验证防御与边界，真实披露文件（约 2,000 份上市公司官方公告原样保存、零修改）度量真实场景表现，两者互不替代、结论不混用。
- 多人协同评审在数据模型层已预留（人工事件含操作者字段），完整的多人并行修改与质证流程列入后续计划。
