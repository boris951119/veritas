# 部署文档（veritas 可运行原型）

> 对应《需求说明》`docs/contest-requirements-S4-2026-10-17.md:79` 交付物清单中的 **「部署文档」** 一格（与「使用说明」并列；本文件只讲怎么从零跑起来）。

目标：在一台没有开发环境的电脑上（主场景 Windows 10/11，次场景 macOS/Linux），从零把 veritas 跑起来。按步骤执行，每步都有明确通过判据；失败按文末「故障排查」处理。本目录即仓库根（含 `app/`、`tests/`、`requirements.txt`）。

## 第 0 步：环境自检

1. 找 Python（需 **3.10+**，3.12 最佳）：
   - Windows：依次尝试 `py -3 --version`、`python --version`；
   - macOS/Linux：`python3 --version`。
2. 都没有或版本 < 3.10：
   - Windows：`winget install Python.Python.3.12`（无 winget 则用安装包，装时勾选 *Add python.exe to PATH*），装完**重开终端**；
   - macOS：`brew install python@3.12`。
3. 建议把仓库放在**纯英文路径**下（如 `C:\veritas`），避免个别第三方库对非 ASCII 路径的兼容问题。

## 第 1 步：建环境装依赖

优先直接跑一键脚本（等价于下面的手工命令）：

- Windows：`setup-windows.bat`（双击或终端执行）
- macOS/Linux：`bash setup-mac.sh`

手工命令（与脚本等价）：

```bat
:: Windows（cmd）
py -3 -m venv .venv
.venv\Scripts\python -m pip install -U pip
.venv\Scripts\python -m pip install -r requirements.txt litellm
```

```bash
# macOS / Linux
python3 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install -r requirements.txt litellm
```

网络慢或不通时，pip 命令追加国内镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`

**注意**：不要拷贝或迁移旧机器上的 `.venv/` 目录——venv 不可跨机移植，必须现场重建。

## 第 2 步：验证安装（不需要任何 API key、不需要网络）

```bat
:: Windows
.venv\Scripts\python -m pytest tests -q
```

```bash
# macOS / Linux
.venv/bin/python -m pytest tests -q
```

**通过判据（两格）**：

| 环境 | 期望 |
|---|---|
| 未装可选依赖 `mcp` | 零 failed；允许 1 条 skip（仅来自 `tests/test_mcp_server.py` 的 `importorskip("mcp")`） |
| 已装 `mcp` | 零 failed 且零 skipped |

**怎么复跑现行基线**（读数会随收口单漂移，以当场命令为准，勿把历史档位当契约）：

```bash
.venv/bin/python -m pytest tests -q
.venv/bin/python scripts/ledger_counts.py   # 抄 pytest_collect_only／def_test_count
```

发单时点名基线＝`932` collect／`916` 定义（见 `docs/HANDOFF.md` 页眉；复算命令同上）。

## 第 3 步：离线演示（断网／无 key 时的完整演示兜底）

```bat
:: Windows
.venv\Scripts\python scripts\demo_offline.py
```

```bash
# macOS / Linux
.venv/bin/python scripts/demo_offline.py
```

**通过判据**：先后打印三个案例的完整研判报告（含多分析师归并、冲突消解、少数意见、防篡改校验），产物分别写入：

- `cases/demo-solid-state/out_offline/`
- `cases/bi-delivery-risk/out_offline/`
- `cases/rumor-vs-official/out_offline/`

各含 `report.json`／`report.md`／`chain.jsonl`。桩客户端离线模拟三分析师协同全流程；产物在 `.gitignore` 内，跑完工作树应仍干净。

## 第 4 步：在线真实研判（需要 API key）

1. 复制 `.env.example` 为 `.env`，填入 `OPENAI_API_KEY` 与 `OPENAI_BASE_URL`（key 向项目负责人索取，**不在仓库里、不在 U 盘明文里**）。可选 `config.json` 覆盖模型清单（参考 `config.example.json`）。
2. 运行：

```bat
:: Windows
.venv\Scripts\python -m app.pipeline cases\demo-solid-state
.venv\Scripts\python -m app.pipeline cases\bi-delivery-risk
```

```bash
# macOS / Linux
.venv/bin/python -m app.pipeline cases/demo-solid-state
.venv/bin/python -m app.pipeline cases/bi-delivery-risk
```

**通过判据**：打印真实研判报告，产物写入 `cases/<案例>/out/`；`chain.jsonl` 为全程哈希链研判日志。

### 大库选料（默认阈值 50）

不配环境变量时，信源数达到 50 才选料；演示小案例整卷研判。达到阈值后材料写入 `cases/<案例>/.corpus/`，再按议题收成小案卷。强制关掉：`.env` 写 `VERITAS_CORPUS_SELECT_MIN=0`。

## 第 5 步：可视化工作台（演示主入口）

```bat
:: Windows
.venv\Scripts\python -m app.server --port 8765
```

```bash
# macOS / Linux
.venv/bin/python -m app.server --port 8765
```

浏览器打开 `http://127.0.0.1:8765/`（默认只读本机）。工作台读取 `cases/*/out*/report.json`：证据链三级下钻、置信度分量、冲突消解与少数意见、信源可信度调整、删证据／改权重即时重算、哈希链校验。若 8765 被占用换端口即可。

## 第 6 步：MCP 标准接口（可选）

```bat
:: Windows
.venv\Scripts\python -m pip install mcp
.venv\Scripts\python -m app.mcp_server
```

```bash
# macOS / Linux
.venv/bin/python -m pip install mcp
.venv/bin/python -m app.mcp_server
```

暴露 6 个标准工具：`list_cases`／`get_report`／`verify_chain`（零 LLM）＋`ingest_external`＋`run_analyst`／`run_judgment`。不装 mcp 不影响前 5 步与测试。

## 故障排查

| 症状 | 处理 |
|---|---|
| pytest 中文报 `UnicodeEncodeError`／GBK | 用 `python -X utf8 -m pytest tests -q` |
| 控制台中文乱码 | `chcp 65001` 后重跑 |
| pip 装不上 litellm | 加镜像参数重试；仍失败可暂时跳过——`pytest` 与 `demo_offline` 不依赖 litellm（懒加载），仅第 4 步在线研判需要 |
| PDF 信源摄取报 pypdf 缺失 | `pip install pypdf`（demo 案例不含 PDF 不影响演示） |
| 要开源版式增强（跨页表等） | `pip install -r requirements-docling.txt` 后设 `VERITAS_PDF_BACKEND=docling`；失败自动回退 pypdf |
| venv 激活后命令找不到 | 直接用绝对路径调 python：`.venv\Scripts\python`（Win）／`.venv/bin/python`（Mac） |
| 测试出现 failed | 把失败摘要原样反馈给开发者；在修好前用第 3 步离线演示兜底 |

## 官方提交物导出（可选）

研判产物就位后，可用导出层写出五份提交 JSON＋《字段说明》：

```bash
# 例：对某跑次目录内各专题 questions/*/report.json 调 export_official
# 详见 scripts/build_submission_zip.py（交件 zip 组包，含三项自查）
PYTHONPATH=. .venv/bin/python scripts/build_submission_zip.py \
  --run-dir /tmp/s4runs/<跑次> \
  --docs-dir docs/deliverables \
  --extra-docs-dir ~/Desktop/veritas-交付物-2026-10-24
```

输出落在 `dist/veritas-交件-<日期>.zip`。**不许把官方样例集原始素材打进包。**
